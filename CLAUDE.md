A CAD application in modern .NET built around a **hybrid geometry kernel** that natively supports three representations:

- **B-Rep** — parametric surfaces (planes, conics, NURBS) wrapped in topology, for precision modeling
- **Implicit** — signed distance fields (SDF) as an AST of primitives and operators, for lattices and organic blends
- **Mesh** — discrete half-edge triangle meshes, for rendering, FEA, and 3D printing

A distinctive design goal is **LINQ-native geometry querying**: a custom `IQueryable` provider inspects expression trees and routes spatial predicates to spatial indexes (BVH/octree) instead of linear scans.

## Architecture

Three engines with different mathematics and data structures, plus interop and query layers on top of a shared core.

### Core (foundation for everything)
- Zero-allocation math: `readonly struct` `Vector3d`, `Matrix4x4d`, quaternions, `AABB`
- Central tolerance/epsilon policy for robust floating-point comparison
- Spatial acceleration: BVH and octree (used by all engines and by the query layer)

### Mesh engine (discrete)
- Half-edge data structure for O(1) topology traversal
- Algorithms: booleans, decimation, subdivision
- Bulk data stored data-oriented (SoA) for cache locality

### Implicit engine (volumetric)
- SDF evaluator: `(x, y, z) → distance`
- Primitives (sphere, box, cylinder, …) and operators (union, intersect, smooth blend) composed as an AST
- SIMD-batched evaluation; later, compilation of C# expression trees down to SDF graphs / IL / compute shaders

### B-Rep engine (parametric) — hardest, built last
- Geometry: planes, cylinders, cones, NURBS surfaces/curves
- Topology wrapper referencing geometry: Solid → Shell → Face → Loop → Edge → Vertex
- Surface–surface intersection engine; booleans and filleting on top

### Interop layer — conversion triangle complete
- Implicit → Mesh: `SurfaceNets.Polygonize` (manifold dual contouring)
- B-Rep → Mesh: `BRepTessellator.Tessellate` (shared edge polylines + ear clipping + welding)
- Mesh → Implicit: `MeshSdf` (BVH nearest-triangle + angle-weighted pseudonormal sign; requires closed mesh; composes with all `Sdf` operators)

### Query layer (LINQ) — v1 implemented
- `SpatialCollection<T>` (items + bounds expression + BVH) with `AsQueryable()`: a custom `IQueryProvider` rewrites expression trees, recognizes `SpatialPredicates` clauses (`.Within(box)`, `.WithinDistance(p, d)`, `.HitBy(ray)`) applied to the registered bounds accessor, answers them from the BVH, and re-applies the full predicate over candidates (interception is a pure optimization). Residual/non-spatial queries fall back to LINQ-to-Objects. `LastQueryUsedIndex` is the diagnostic.
- IMPORTANT: query predicates use the by-value `SpatialPredicates` extension methods, NOT `Aabb.Intersects` — expression trees cannot contain calls with `in` parameters, which the kernel API uses.
- Topology-traversal LINQ exists on mesh handles (`vertex.OutgoingHalfEdges().Where(...)`, `face.AdjacentFaces()`, `Face.Bounds`).
- Future: metadata indexes for B-Rep feature queries (cylindrical faces by radius), expression-tree→SDF compilation.

## Performance mandates (non-negotiable in kernel code)

- Math types are `readonly struct`; hot paths allocate nothing on the heap
- Use `Span<T>`/`Memory<T>`; temporaries come from `ArrayPool<T>` or `stackalloc`, never `new` per call
- Use `System.Runtime.Intrinsics` (SIMD) for SDF evaluation, ray/primitive intersection, and other batch kernels
- Bulk mesh data uses structs-of-arrays, not arrays-of-objects
- Never compare floats with `==`; all comparisons go through the central tolerance policy in `EngrCAD.Core`
- **Degeneracy guards on areas and determinants must be RELATIVE, never absolute** (the BSP lesson's second occurrence): `Sketch`'s enclosed-area, arc-chord and `ArcThrough` circumcenter guards were absolute 1e-12 and therefore wrong in *both* directions — a legitimate 1 µm × 0.5 µm pocket was rejected as enclosing no area, while a 1000 × 1e-10 sliver passed; three metre-scale points 1e-10 off a line built a radius-1.25e15 circle. They now scale by extent² / magnitude² (`Sketch.RelativeDegeneracy`), because an area is quadratic in scale. Deliberately still absolute, with reasons in code: sketch closure (the 1e-9 weld tier) and sweep angular guards (radians are dimensionless).
- **The epsilon ladder** (audited repo-wide; every site is documented in place): new epsilons must pick a tier — **1e-9 absolute weld** (= `Tolerance.Default.Linear`: exactly-constructed shared geometry — tessellation welds, seam breaks, clone dedupe) / **1e-7 seam** (geometry built independently on two sides of one curve — `SealSeams`, boundary-vs-grid matching, MeshWelder zip) / **1e-6 inverse-evaluation** (named: `FaceGeometry.InverseEvaluationTolerance` — Gauss–Newton pullback; three decades looser than weld, do not tighten; the 1e-7 seam tier is likewise named `FaceGeometry.SeamTolerance`, and `SurfaceIntersection`'s marching constants live together in `TracerSettings` because they must be tuned as a set) / **scale-free algorithmic guards** (relative machine-epsilon degeneracy tests, exact-zero division guards, exact-zero *semantic* tests — these deliberately bypass `Tolerance` and say so in a comment). Never invent a fresh literal. Shewchuk `Predicates2d` error-bound constants are the algorithm — off limits.

A crossing that coincides with an **existing vertex** must be reconciled to one coordinate **across both meshes** before either imprint runs, honoring any mapping the crossing already carries, or the seam silently stops welding. Inside/outside must be decided **per patch at the largest triangle's centroid**, never per face — seam slivers sit exactly where the winding number approaches ½ (the same lesson `BrepBoolean` learned about sagitta-safe probes). And degeneracy guards here are `1e-13 × operand extent` — the scale-free tier, never the absolute weld tier — which is what makes small models and near-tangent pairs work. **Two more traps, both found by the coincident-surface work, both the same defect in new clothes**: never call `Vector3d.TryNormalize(Tolerance.Default)` inside a scale-free algorithm — it applies the absolute 1e-9 to a **cross product**, i.e. an *area*, so mating faces stopped being recognized below ~1e-4 scale (measured: a non-manifold union at 1e-5 — the BSP defect reintroduced inside the very algorithm that exists to avoid it; read only the *sign* of the area-weighted normal instead). And **`Orient2d` returns twice an AREA**, so an epsilon compared against it must be scaled by the edge length — unscaled, coplanar triangles that merely *touch along a shared edge* (the commonest relation between neighbouring solids) report as overlapping. **Performance lesson, the same shape as the B-Rep boolean's**: the two biggest costs were an O(k²) scan of every fragment ever cut from a host face when locating interior seam points (96% of the imprint for a 64-sided bore), and **building an O(n log n) winding hierarchy to answer eight questions** — below ~32 queries the exact O(n) sum is the faster algorithm (`MeshWindingNumber.Direct`; two 32k-triangle spheres went 65 ms → 6 ms). Also: `HalfEdgeMesh.Triangulated()` was rebuilding meshes that were already triangles, revalidating everything per boolean stage in a cascade. **HoleFiller** (simple fan + planar nested-hole earcut on `FitPlane3` frames — orientation intrinsic from boundary walk order, ring-aware chord zip repairs earcut's collinear filtering; fills the annular caps `MeshPlaneCut` refuses); **MeshExtrude** (patch extrude + open-surface thicken — wall quads are exactly the directed edges freed by moving the patch, winding correct by construction); selections (immutable Grow/Contract) + connected components (per-component area/volume/closed + extraction); viewer renders meshes
3. **Implicit engine** ✅ done — `Sdf` AST (`Evaluate`/batch/`Normal`/conservative `Bounds`), primitives (sphere, box, cylinder, torus, capsule, half-space, gyroid lattice), operators (union/intersect/subtract with `|`/`&`/`-` overloads, smooth blends, offset, shell, translate/rotate/scale; **N-ary** `Sdf.Union`/`Intersection`/`SmoothUnion` as flat single-node loops — children evaluated once per query; the N-ary smooth union folds the pairwise polynomial smooth min, so it matches chained binary exactly and reduces to hard min outside the blend band; `Sdf.Blend(a, b, d, Falloff.Wyvill|Exponential)` falloff-kernel blend whose bump is bounded by the blend distance — Wyvill's compact support makes it *exactly* union outside the band; smooth-op bounds clamp their expansion at 0 for blend ≤ 0; **sampled grids**: `Sdf.Sampled(cellSize[, region][, lazy])` bakes any `Sdf` to a dense or lazy 16³-block trilinear grid through the batch `Evaluate` seam — exact at nodes, O(h²) between, outside the box = boundary value + distance-to-region — the standard acceleration for expensive ASTs like `MeshSdf`); `SurfaceNets.Polygonize` in Interop converts implicit→mesh (manifold variant: one vertex per inside-corner component per cell). **SIMD batch evaluation** (`BatchEvaluation.cs`): the batch entry deinterleaves AoS→SoA **once at the AST root** (pooled 1024-point chunks) and drives an internal `EvaluateBatch(x, y, z, distances)` seam that operators forward straight to their children, so the transpose is paid once per batch rather than per node; kernels use width-agnostic `Vector<double>` (one kernel serves NEON/AVX2/AVX-512). **Bit-for-bit identical to the scalar path** — each kernel mirrors its scalar form term-for-term in the same association order, the ragged tail falls back to scalar, and tests assert `DoubleToInt64Bits` equality over a 41-node catalogue at randomized *and* structured (on-surface/edge/corner) points and every batch length around the register and chunk boundaries; the one documented deviation is that `Vector.Min/Max` break a ±0 tie by operand position rather than by sign. The suite also passes under `DOTNET_EnableHWIntrinsic=0`, so the no-SIMD fallback is exercised, not assumed. Gyroid, exponential falloff and `ThreadSdf` stay scalar on purpose (no vector transcendental reproduces `Math.Sin`/`Math.Exp` bit-for-bit, and a silently divergent fast path is worse than none). Measured ~3.5× on CSG trees and ~3× on `Sampled` bakes — but honestly, a bare **sphere is 0.81×** (a five-flop kernel cannot pay for the transpose at 2 lanes; this inverts on 4/8-lane x64). **`Sdf.NarrowBand(cellSize[, region][, bandWidth])`**: evaluate the source only near its surface (octree culling, sound because distance is 1-Lipschitz and the field's magnitude is a lower bound on it) and fill the rest with a **two-scan chamfer transform** — one causal plus one anti-causal raster pass is the complete distance, no iteration to convergence, and no ray-parity signing is needed because an `Sdf` is sign-exact. 8–11× faster than a dense bake for `MeshSdf`, and honestly documented as **3–10× *slower* for cheap analytic fields** (the outward fill costs ~60 ns/sample and raster scans don't parallelize). Outside the band the sign stays exact but the magnitude over-estimates by up to ~13% (Borgefors' anisotropy bound; measured 1.112× worst case). Two perf lessons worth keeping: **the AoS→SoA transpose must be written against raw references** — four span bounds checks per point cost more than a cheap kernel saves, and going through indexers halved `Sdf.Box` throughput; and **JIT tiering makes single-warm-up benchmarks meaningless** (the same code measured 147, 314 and 548 Mpts/s across runs — use a wall-clock warm-up *budget*, not a warm-up count). Future: expression-tree→SDF compilation for the Query layer
4. **B-Rep engine** 🔶 modeling operations done — curves (`Line3d`, `Circle3d`, `Ellipse3d`, **`Parabola3d`/`Hyperbola3d`** (focal / cosh-sinh parameterizations completing the analytic conic family; parabola has closed-form arc length) and **`OffsetCurve3d`** (planar offset as first-class geometry, exact O′ = (1 − dκ)·C′ — |d| vs curvature radius deliberately unvalidated, as OCCT), with **`Curve3d` exposing virtual `DerivativeAt`/`SecondDerivativeAt`** overridden exactly by every analytic curve and wrapper; `NurbsCurve` with exact rational conics, **exact analytic derivatives** (`DerivativeAt`/`SecondDerivativeAt` via The NURBS Book A2.3 + the rational quotient rule; `TangentAt` overridden — the finite-difference note below now applies only to curves without an exact override) and **`NurbsCurve.InterpolatePoints`** (chord-length parameterization, natural-end open cubic via tridiagonal Thomas solve, or C2-seam closed periodic; exact pass-through), `ReversedCurve`/`TransformedCurve` wrappers with `Underlying` for sampling rules), surfaces (`PlaneSurface`, `CylinderSurface`, `SphereSurface`, `NurbsSurface`, `ExtrudedSurface`, `RevolvedSurface` with angle, `SweptSurface` with rotation-minimizing frames), topology (`BrepSolid`→…→`BrepVertex` with `Validate` + Euler–Poincaré incl. genus), `SolidFactory`: `MakeBox`/`MakeCylinder`/**`MakeCone`** (frustum or apex — the side is an exact `RevolvedSurface` of a slanted line generator, deliberately NOT a new surface type: the revolved-band machinery already provides projection/tessellation/intersection/wrap-split/STEP; rim circles built on the surface's own radial frame stay phase-aligned with u=0; a zero radius makes that end a pole like sphere poles) + **`Extrude` (incl. shear + hole profiles), `Revolve` (full or partial turn, holes on partial, pipe elbows from closed profiles), `Sweep` (RMF along open paths, holes)** over `Profile` (planar closed chain; winding auto-corrected). **Mesh engine additions**: `ConvexHull` (quickhull: extent-scaled epsilon for all visibility tests, coplanar points absorbed by consistent triangulation, degenerate inputs throw, output passes manifold-validating Build) and `HalfEdgeMesh.Transformed(Matrix4d)` (negative-determinant transforms flip winding so meshes stay outward-oriented). **`Shape.Cone`** (Native all three reps), **`Shape.Hull`** (mesh-construction: B-Rep-Impossible, implicit/mesh Bridged via quickhull over tessellated vertices — exact for polyhedral operands), **`Shape.Mirror(point, normal)`** (Householder reflection through the transform node; implicit-**exact** — the compiler decomposes improper similarities as m = (m·FlipZ)·FlipZ, lowers at identity, wraps `Sdf.Mirror`, places the proper remainder; mesh exact with winding flip; B-Rep Native for box/cylinder/extrude/sphere/torus/cone — mirrored cylinders keep exact `Circle3d` rims because FlipZ fixes the rim plane — but mirrored revolve/sweep/rim/drill stay Impossible in v1, exact via mesh/SDF instead). `BRepTessellator` handles planar (multi-loop, earcut) /cylinder/extruded/revolved/swept faces with edge-consistent grid sampling and seam zipping. Notes: default `Curve3d.TangentAt` uses 2nd-order one-sided differences at domain ends (sweep frames are sensitive to start-tangent error); `PolygonTriangulator` is a faithful mapbox-earcut port — its collinear filtering can merge exactly-collinear boundary runs, which the tessellator's zip pass repairs. **Surface–surface intersection done** (`SurfaceIntersection.Intersect(a, b, region)`): analytic curves for plane/plane (line), plane/cylinder (circle, ellipse, or parallel lines), plane/sphere, sphere/sphere, parallel cylinders; general marching tracer (grid seeding + BVH pairing + damped Gauss–Newton refinement + tangent-predictor/Newton-corrector stepping, periodic-aware, multi-branch, closed-loop detection) for all other pairs, returning `PolylineCurve3d` (exact at vertices, chordal between). New curves: `Ellipse3d`, `PolylineCurve3d`. **Trimming groundwork done**: `Surface.TryProjectPoint` (inverse evaluation — exact for plane/cylinder/sphere, Gauss–Newton otherwise), `FaceGeometry` (curve pullback into parameter space with periodic-u unwrapping, `LoopSignedArea`, point-in-face by upward-v ray parity with periodic segment compaction), `FaceSplitter.SplitByClosedCurve` (closed interior curves → face-with-hole + disk sharing one manifold edge; `createDisk:false` hands the edge's second use to another face). End-to-end drill rehearsal in `DrillTests`: box + intersection circles + cap splitting + bore-wall assembly → valid genus-1 solid with exact volume. **Open-curve face splitting done**: `TopologyEditor.SplitEdge` (splits an edge at a parameter, patching every using loop — neighbor faces stay consistent), `FaceSplitter.SplitByCurve` (full parameter-space arrangement: polyline crossing detection + 2×2 Newton refinement, boundary-edge splitting with endpoint-vertex reuse, interior curve segments as shared two-use edges via `CurveSegment`, sub-face tracing by smallest-clockwise-turn walking, CW loops assigned as holes to their smallest containing CCW loop). Verified through whole solids: single cut (exact volume), cross cut through a split-created vertex (4 quadrants), annular cap cut beside its hole (hole follows the correct side). **Trimmed-face tessellation + cut-through-hole booleans done**: `TrimmedFaceTessellator` (Interop) renders faces whose loops don't cover the surface's grid domain — exact-coordinate ear clipper (shortest-diagonal ears, ~1e-9 jitter blocking band, hole bridging) + strip-zip/pole-fan for band regions + surface-exact midpoint refinement (Steiner-by-refinement, no upfront classification); routing is a two-sided 3D match of loop samples against the natural grid boundary (the welding invariant, so existing faces can't misroute; trimmed failure falls back to grid). **Never earcut pulled-back curved-face loops** — `PolygonTriangulator` filters exactly-collinear vertices and iso-parameter runs ARE exactly uv-collinear but not 3D-collinear: a dropped sample is an unzippable crack, and jittered earcut breeds zero-area folds that refine into non-manifold welds. `FaceSplitter` hardened for the boolean path: tolerant partial-curve pullback runs (extrapolated run-end seeds), crossing refinement by 3D curve–curve Gauss–Newton (projected-uv Newton fails near bounded domain edges), inclusive crossing seeds (cuts through split-created vertices), and **reversed-face splitting** (CW-aware tightest-turn tracing, `IsReversed` preserved — cascaded booleans on boolean output need this). `BrepBoolean`: both sides of a shared closed intersection curve take a mandatory seam break at `Domain.Start` (the wrap-split side anchors its seam vertex there), and probe points prefer the largest fragment triangle's centroid (sliver centroids sit within the SDF's sagitta of the other solid's curved surface — misclassification). End-to-end: drilled box minus a slot narrower than the bore → Validate-clean genus-3 solid, closed manifold tessellation, volume within 7e-4 of analytic. Two-ring band faces with hole loops tessellate properly (seam in the largest u-gap, unrolled + ear-clipped with hole bridging; tracer `PolylineCurve3d` edges are sampled at exact vertex parameters — uniform sampling lands on chords ~1e-4 off-surface); `Refine` terminates via a monotone-decrease enqueue rule with fail-safe fallback. Remaining trimmed-face gaps: pole-bands-with-holes and |winding|>1 fall back to grid, no Delaunay quality flips. **Sphere-piercing booleans fixed** (was: silent wrong geometry when a sphere pierces box faces so every intersection curve is a closed circle interior to a face) — lessons: `BrepQueries.Bounds` must sample surface domains, not just edges (a hemisphere's equator-only edges hid the dome from the face-pair prefilter); tracer-clipped arcs can NEVER be refined against a boundary they stop short of — promote full-turn revolved spheres to exact analytic plane∩sphere circles (`TrySphereCarrier`, generator sampled, never `Underlying`); closed interior curves need mandatory seam breaks honored on BOTH sides (`SplitByInteriorClosedCurve` builds matching arc pairs); period-wrapping traced loops are band boundaries paired bottom-to-top by v, not area-classified holes. `Shape.Drill` validates up front (overlap/tangency per point pair; far-face coplanarity at B-Rep lowering via the `DrillShape` node) instead of failing deep in tessellation. **Cross-drill-through-bore booleans fixed** — the root cause was NOT the wrap-split but silent no-op pullback: tracer polylines sampled at uniform parameters sit step²/8r (~1e-4) off the carrier surface, past the 1e-6 inverse-evaluation tolerance, so `PullCurveRuns` returned zero runs and unsplit bands were whole-classified away. Lessons now baked in: **tracer polylines are on-surface only at their vertices — ALL pullback/parity/crossing sampling goes through one shared rule** (`FaceGeometry.ExactSampleParameters`: polylines → vertex parameters, `CurveSegment`-over-polyline → mapped base vertices, else uniform), never per-call-site patches; a **non-planar wrap cut cannot become a domain boundary** — `SplitBandByNonPlanarWrapCurve` sub-bands keep the original surface and rely on trimmed-face tessellation (the trim-the-surface rule applies only to constant-parameter cuts); multiple wrapping cuts on one band decide containment **per fragment by loop parity** (every fragment shares the full carrier, so every cut pulls back onto all of them). Equal-radius perpendicular cylinders (tangent bicylinder) are rejected loudly (overlapping v-ranges). **Automatic B-Rep booleans done** (`BrepBoolean.Union/Intersection/Difference` in Interop): per-face-pair `SurfaceIntersection`, seam-aligned splitting (each side takes the other's crossing params as mandatory breaks so tessellation welds), fragment classification by probing the other solid's `MeshSdf` (hybrid trick), reversed faces for subtracted tools (`BrepFace.IsReversed`, tessellator flips), wrap-splitting of periodic bands (`SplitBandByWrapCurve`: bore wall → two exactly-reconstructed sub-bands), and circle-extrusion→cylinder promotion for exact bore circles. Boolean output is **topologically sealed** (`TopologyEditor.SealSeams`: stale-use pruning, vertex unification, seam-edge merging; Difference re-winds reversed faces' loops) — results pass `Validate()` and Euler–Poincaré with correct genus. **Loft / draft / shelling** (kernel-level; `Shape` API wiring + docs still owed): `SolidFactory.Loft(sections, Smooth|Ruled)` skins a solid through profiles via `LoftedSurface`, P(u,v) = Σ αₖ(v)·Cₖ(uₖ) where α is the **cardinal basis of B-spline interpolation, inverted ONCE at construction** — that is the load-bearing decision, because a chord-length reparameterization recomputed per u gives every strip its own v mapping and cracks every shared rail; αₖ(v_j) = δⱼₖ holds by exact equality, so the v=0/v=1 grid rows reproduce the end sections bit-for-bit. Mismatched segment counts are rejected (no degree elevation yet); alignment minimizes **centroid-relative** squared corner travel — *the lesson*: leaving the sections' separation in that objective makes it a large constant plus a tiny quadratic well, which cost eight digits and left 3e-8 of residual twist, past the weld tolerance. `Draft.Apply` rotates each selected face's plane about its **neutral line** by exactly the angle (n′ = n·cosθ + p̂⊥·sinθ, corners by three-plane Cramer solves), so it is closed-form, composable (twice by θ/2 == once by θ to 1e-12) and still emits selectable `PlaneSurface` faces; curved faces, holed caps and profile-folding tapers are rejected loudly. `Shelling.Offset/Shell` is the B-Rep counterpart of the SDF-only `Shape.Shell`, exact for polyhedra (an offset plane is a plane; offset vertices are three-plane intersections), carrying topology verbatim so a plate's outline shrinks while its bore *grows*; no opening ⇒ sealed void as a second shell, two openings ⇒ genus-1 tube. Curved faces and >3-valent vertices are rejected because their **corners** need surface–surface re-intersection — the *same* missing machinery as sharp-corner fillet patches. **Filleting**: `Filleting.FilletEdge` for closed circular rims (planar cap ↔ coaxial cylinder band) via exact quarter-torus `RevolvedSurface`; general fillet chains with corner patches are future work. **STEP export + import**: `StepWriter.Write/WriteFile` (AP214 `MANIFOLD_SOLID_BREP`, analytic surfaces/curves incl. rational NURBS, wrapper-curve simplification; swept surfaces not exportable) and `StepReader.Read/ReadFile` (full Part 21 parser + AP214 entity mapping back to `BrepSolid`; round-trips everything the writer emits — topology shared by entity identity, edge domains reconstructed exactly from vertex positions (closed-form conic phases, Newton with exact derivatives for B-splines), `SURFACE_OF_REVOLUTION` angle/generator-trims recovered from rails/rims by **bisection on the exact (radius, axial) profile residuals** (root solves — distance minimization stalls at √ε ≈ 1e-8, past weld tolerance); mm assumed, unknown entities skipped with diagnostics; verified on box/cylinder/drilled-plate genus-2/revolves/booleans/fillets at ~1e-12 volume agreement; known-lossy: `TransformedCurve(NurbsCurve)` exports as sampled degree-1 polylines). **Viewer picking**: click-select via unprojected ray + per-object triangle BVH + Möller–Trumbore, selection highlighted and named in the title bar (note: Avalonia's pointer stack ignores legacy synthetic `mouse_event` clicks — BUT **`SendInput` works**: synthetic clicks and drags injected via `SendInput` (absolute normalized coordinates, window activated first) DO reach the pointer stack, so interactive viewer features can be driven and screenshotted end-to-end rather than only exercised by calling `Pick`/`Select` directly). Remaining future work: coplanar/tangent boolean cases, fillet gaps that remain after the corner work (non-perpendicular trihedral corner patches, partial edge runs, arc-rim sharp corners, variable radius), NURBS surface export, STEP unit scaling + conical/toroidal surface synthesis. **Inverse evaluation on a swept surface is a ONE-dimensional solve — this was ~100% of the B-Rep boolean's cost.** `ExtrudedSurface`/`RevolvedSurface` override `TryProjectPoint`: an extrusion's `v` is fixed by the direction component, so only `Q(C(u) − p)` constrains `u`; a revolve's `u` is the azimuth in closed form once `v` matches the generator's (radius, axial) profile. Both scan the *generator alone* at the base class's u resolution and refine with 1D Gauss–Newton on the exact `DerivativeAt`. The generic base scans a **17×17 (u,v) grid that re-evaluates the same generator point once per column — 289 curve evaluations where 17 carry all the information** — and since inverse evaluation is the inner loop of every face pullback, it dominated everything: 7-glyph engraving **65.3 s → 4.0 s**, a 5-hole drilled plate **14.4 s → 1.7 s**, the Interop test suite **4m16s → 22 s**, DocsGen **106 s → 41 s**, with volumes bit-identical and not one of the 37 rendered docs PNGs changing a byte. Profiling first was essential: the two *plausible* culprits (an over-conservative face-pair prefilter, and face-splitting/`SealSeams`) were both innocent — only 113 of 894 pairs survive the prefilter and all 113 intersections resolve in ~1 ms. **When a surface is a sweep, never inverse-evaluate it in 2D.** (`SweptSurface`/`NurbsSurface` still use the base grid, legitimately — an RMF frame varies along the path.) `Scene.PreMesh` and `AmbientOcclusion.Prime` also prime parts **in parallel** now (`ParallelFor.Blocks`; parts are independent by construction and the first failure *in scene order* is rethrown with its original stack, never a scheduling-dependent `AggregateException`). **Sketch-extrusion booleans (pockets, slots, engraving) are exact** — the fix for a silent open-mesh bug, and its lessons are load-bearing: an extrusion of a straight generator IS a plane, but a **bounded** one, so the analytic line must be clipped to the generator's parallelogram, not merely to the query region (`TryPlanarPatch`/`PlanarPatches`, straightness decided by sampling the actual generator at the weld tier — `Underlying` is only a type hint). Better still, when the generator's plane is **parallel to the cutting plane** the section is exactly the generator *translated* by `direction·v` (`TryPlaneExtrudedSection`): exact for ANY generator shape (lines, slot arcs, glyph Béziers), and — the load-bearing property — its endpoints come from the generator's own points, so consecutive profile segments hand over their shared corner **bit-for-bit** and the outline closes. Note the precondition is NOT "plane ⊥ direction", which is why sheared tools are exact too. **The marching tracer breaks its step AFTER `Correct` leaves the domain, so it always stops up to one march step short of a bounded generator's ends — never use it where a curve must terminate exactly on a boundary** (measured: cuts missing corners by 0.015–0.284 mm, so the outline never closed). Worse, when truncation left no usable curves at all, the disjoint fast path buried the tool as an internal cavity: a closed, `Validate`-clean solid with the *wrong* volume. `BrepBoolean.Verified` now enforces two-manifold output and throws `BrepBooleanException` naming the operation, counting unpaired edges, locating a crack, and suggesting the implicit route — but it catches **unclosed, not wrong-but-closed**, so end-to-end boolean tests must assert analytic volumes. Numerical notes from the Modeling work: the generic `Surface.TryProjectPoint` wraps (not clamps) periodic u so Newton can cross the seam; plane⊥cylinder intersection circles are **phase-aligned to the cylinder's frame** (arbitrary-perpendicular frames caused tessellation cracks on rotated bores — and `DrillTests` winding depends on this); `BrepBoolean.ProbePoint` routes full-period-wrapping loops to the band path (projection jitter gives degenerate sliver loops nonzero area, and the planar path would probe on the fragment boundary where the SDF is 0); `SurfaceIntersection.Promote` sanity-checks that the generator lies on the candidate cylinder (a `TransformedCurve`-wrapped circle's `Underlying` is the untransformed circle).
